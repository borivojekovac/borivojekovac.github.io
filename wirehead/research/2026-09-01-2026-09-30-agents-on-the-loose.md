# The Agent Has a Keyring

Period: September 1-30, 2026  
Impact: Critical  
Theme: Agent infrastructure, memory, permissions, security

## Executive Summary

September supplied the missing middle layer of the agent story. The demos were not the headline. Sandboxes, state stores, orchestration systems, identity boundaries, and review queues were.

OpenAI launched an Agents API with managed sandboxes and subagents. Google open-sourced an orchestration layer modeled on Kubernetes. OpenAI described storage designed for more than a billion users, while Google worked on encrypted server-side memory. DoorDash used agents to clean up tens of thousands of feature flags. Meta pushed Muse from a personal assistant into avatars, wearables, and computer use.

The common thread is simple: an agent is useful because it has a keyring. The month was about who holds that keyring, where it is stored, and what happens when the agent uses it in a way nobody intended.

## The operating system around the model

OpenAI's Agents API made the environment explicit. Its public beta included a Codex-style harness, hosted sandboxes, managed subagents, and tools for longer-running work. That is a product boundary around the model: a place to execute, persist, delegate, and inspect. ([OpenAI's Agents API announcement](https://openai.com/index/introducing-agents-api/))

Google's AX project made a similar argument in open-source form. Its Kubernetes-style approach treated agents as stateful services with lifecycle and coordination requirements. A model can generate a plan, but an orchestration layer decides whether the plan gets a process, a network route, a credential, or another agent.

That distinction will matter more as enterprise systems move from assistant features to agent fleets. The hard part is not making one tool call. It is knowing which subagent acted, under which policy, with which version of a model, against which data, and whether a human had a chance to stop it.

## Memory is infrastructure, not a feature toggle

OpenAI's Habitat storage work described the scale problem behind persistent state: more than one billion ChatGPT users and roughly 20 million requests per second. Google, meanwhile, proposed server-side memory in secure enclaves so an assistant could remember across devices without making private context visible to the service operating the model. ([OpenAI on Habitat](https://openai.com/index/scaling-storage-one-billion-users-part-one/), [Google on private server-side memory](https://deepmind.google/blog/advancing-private-ai-compute-with-secure-server-side-memory/))

Memory changes the threat model. A stateless chatbot can leak a prompt. A persistent agent can accumulate a profile, retain a secret, learn a workflow, and act on a user's behalf weeks later. The architecture must answer questions that product copy tends to avoid: what is remembered, for how long, who can delete it, and can an agent distinguish a durable instruction from a temporary request?

## The useful agent is supervised

DoorDash's feature-flag cleanup is an instructive enterprise case. Agents analyzed about 60,000 flags across hundreds of repositories and created pull requests. The reported success rate was encouraging, but the workflow still depended on human approval and isolated worktrees. ([InfoQ on DoorDash's cleanup](https://www.infoq.com/news/2026/09/doordash-feature-flag-cleanup/))

That pattern is likely to be durable. Agents can do reconnaissance, ranking, drafting, testing, and repetition. Humans retain responsibility for merges, production changes, and ambiguous judgment. The productivity gain comes from giving the agent a large search space while keeping the final authority narrow.

Meta's Muse shows the consumer version of the same bet. A personal agent gets more compelling when it has memory, a visual identity, a computer-use surface, and hardware around it. It also gets riskier. A virtual machine can contain some actions, but it cannot by itself solve consent, impersonation, or the social pressure created by an always-available synthetic companion. ([TechCrunch on Muse](https://techcrunch.com/2026/09/23/everything-new-coming-to-metas-ai-agent-muse/))

## Wirehead takeaway

Build the control plane before the agent swarm. Treat identity, memory, sandboxing, review, and rollback as core product surfaces. If an agent cannot explain what it did and surrender its credentials cleanly, it is not an employee. It is an unattended process with a persuasive user interface.
